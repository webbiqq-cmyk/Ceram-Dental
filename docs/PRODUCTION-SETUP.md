# Ceram Dental — Production Setup

Architecture: **Vercel** (frontend) · **Render** (API) · **Render PostgreSQL** ·
**Cloudflare** (DNS + Access) · **GoDaddy** (registrar) · **Cloudinary** (files) ·
**SMTP** (email).

The codebase is prepared for this. Nothing below requires a code change —
only provider configuration.

---

## Production DNS / subdomain map

| Host | Serves | Sits behind |
|---|---|---|
| `www.cerampro.com` | Public website (Vercel) | Cloudflare (public) |
| `portal.cerampro.com` | Dentist Portal (Vercel) | Cloudflare + **Cloudflare Access** (remote OK) |
| `admin-private.cerampro.com` | Admin Portal (Vercel) | Cloudflare + **Cloudflare Access** (remote OK) |
| `lab-private.cerampro.com` | Lab Studio (Vercel) | Cloudflare + **Cloudflare Access**, clinic IP only |
| `api.cerampro.com` | Render API | Cloudflare (proxied) |

All four Vercel hosts serve the **same SPA build**; the backend enforces
role + section + (for lab) IP. `admin-private` / `lab-private` are
deliberately unguessable-ish and never linked from the public site.

## 1. GoDaddy (registrar)

- Keep the domain registered at GoDaddy.
- Change the domain's **nameservers** to the two Cloudflare nameservers shown
  when you add the site in Cloudflare. That is the only GoDaddy change.
- Do **not** set A/CNAME records at GoDaddy — all records live in Cloudflare.

## 2. Cloudflare (DNS + security)

DNS records (all **Proxied / orange cloud**):

| Type | Name | Target |
|---|---|---|
| CNAME | `www` | `cname.vercel-dns.com` (Vercel shows the exact value) |
| CNAME | `portal` | `cname.vercel-dns.com` |
| CNAME | `admin-private` | `cname.vercel-dns.com` |
| CNAME | `lab-private` | `cname.vercel-dns.com` |
| CNAME | `api` | `ceram-dental-api.onrender.com` |
| CNAME/A | `@` | redirect to `www` (Cloudflare Redirect Rule) |

SSL/TLS: **Full (strict)**. Enable **Always Use HTTPS**, **HSTS**
(6 months, includeSubDomains), **Automatic HTTPS Rewrites**.

**Cloudflare Access (Zero Trust)** — one application per private host:

- `admin-private.cerampro.com` → policy: allow specific admin emails / an
  IdP group. Session ~8h. Remote access allowed.
- `lab-private.cerampro.com` → policy: **Require** → *IP ranges* = the
  clinic's static public IP (and, optionally, an allowed email list AND the
  IP). This is the outer gate; the API also checks the IP itself (below).
- `portal.cerampro.com` → optional Access app for extra assurance, or leave
  it on backend auth only (dentists self-register).

The API (`api.cerampro.com`) stays **proxied but not behind Access** — the
browser calls it directly with the session cookie. `TRUST_PROXY=cloudflare`
makes the API trust `CF-Connecting-IP` only from verified Cloudflare edge
IPs, so the clinic-IP allowlist can't be spoofed.

WAF: enable the Cloudflare Managed Ruleset; add a rate-limit rule on
`api.cerampro.com/api/auth/*` (e.g. 20 req / 10 min / IP) on top of the
app's own limiter.

## 3. Render (API + database)

1. **New → Blueprint** → point at this repo. `render.yaml` provisions the web
   service + a PostgreSQL instance and runs `npm run migrate` on every deploy.
2. Fill the `sync:false` env vars in the Render dashboard (values from
   `.env.example`): `COOKIE_DOMAIN`, `WEB_URL`, `PORTAL_URL`, `ADMIN_URL`,
   `LAB_URL`, `API_URL`, `CLINIC_IP_ALLOWLIST`, all `CLOUDINARY_*`, all `SMTP_*`.
3. `JWT_SECRET` is auto-generated by the blueprint. `DATABASE_URL` is wired
   from the managed DB automatically.
4. First deploy: migrations 001–010 run automatically. To seed the first
   real admin, open a Render **Shell** and run:
   `node -e "require('./scripts/setup')"` (or use `POST /api/admin/users`
   once one admin exists — see below).
5. Add `api.cerampro.com` as a **custom domain** on the Render service.

**Bootstrapping the first admin** (no admin exists yet): temporarily set
`DEMO_MODE=true` is *not* acceptable for production. Instead run this once in
the Render shell:
```
node -e "(async()=>{const a=require('./src/services/auth.service');const u=require('./src/models/user.model');const h=await a.hashPassword(process.env.SEED_ADMIN_PW);console.log(await u.createUser({username:process.env.SEED_ADMIN_USER,passwordHash:h,role:'admin',name:'Practice Admin'}));process.exit(0)})()"
```
with `SEED_ADMIN_USER` / `SEED_ADMIN_PW` set for that shell session only.

## 4. Vercel (frontend)

1. Import the repo as a Vercel project.
2. Replace `vercel.json` with `deploy/vercel.split.json` (frontend-only +
   `/api/*` → Render rewrite). Edit the two `api.cerampro.com` references in
   it if the API host differs.
3. Set `public/index.html` `<meta name="ceram-api" content="https://api.cerampro.com">`
   (or rely on the rewrite and leave it blank — the rewrite keeps requests
   same-origin from the browser's view, which avoids CORS entirely).
4. Add all four hostnames as **Domains** on the project: `www`, `portal`,
   `admin-private`, `lab-private`.
5. No secrets in Vercel — the frontend has none.

> If you keep the current monolith `vercel.json` (API on Vercel too), skip
> steps 2–3; everything still works, Render just isn't used.

## 5. Cloudinary

- Create the account; copy `CLOUDINARY_CLOUD_NAME/API_KEY/API_SECRET` into
  Render.
- Create an **unsigned upload preset** named to match
  `CLOUDINARY_CASE_UPLOAD_PRESET`:
  - Signing mode: **Unsigned**
  - Delivery type: **Authenticated** (private; not publicly fetchable)
  - Resource type: **Auto** (image + raw)
  - Access mode: **Authenticated**
  - Max file size: e.g. 15 MB; allowed formats: `jpg,png,webp,pdf,stl,ply,obj,zip`
  - Folder: `ceram-dental/cases`
- Case downloads are already served as **5-minute signed URLs** by the API
  (`src/utils/filePolicy.js`); the backend checks the user can access the
  order before issuing one. No public case URLs are ever produced.

## 6. SMTP

- Any provider (the clinic's mailbox host, or a transactional service).
- Set `SMTP_HOST/PORT/SECURE/USER/PASS/FROM` on Render only.
- Add SPF/DKIM records for the `FROM` domain in Cloudflare DNS.
- Used for: password reset, (optional) email verification, case
  notifications, admin alerts. Unconfigured = these silently no-op.

## Security posture (already in code)

- Passwords: **bcrypt cost 12**, constant-time compare, username enumeration
  defended.
- Sessions: signed JWT in **HttpOnly + Secure + SameSite=Strict** cookies,
  server-side revocation table, 12h / 30d (remember) expiry, `COOKIE_DOMAIN`
  for subdomain sharing.
- **RBAC on every sensitive endpoint** (`requireRole` / `requireAnyRole` /
  `requireWorkflowRole`) — never relies on the frontend.
- **Lab Studio**: auth + lab role + **clinic IP allowlist** (`requireClinicIP`,
  `CLINIC_IP_ALLOWLIST`) → `403` off-network. Real IP resolved safely behind
  Cloudflare (`CF-Connecting-IP` only from verified CF edges; raw
  `X-Forwarded-For` never trusted).
- **Admin**: separate route, `admin` role on backend, rate-limited login
  (8 / 15 min / IP), soft account lock after 8 failures, session expiry,
  **MFA-ready** (`users.mfa_enabled/secret`, `mfa.service.js` hook — fails
  closed), every login success/failure + sensitive action **audited**
  (`audit_logs`: user, role, action, resource, IP, session, timestamp).
- **Dentist / IDOR**: `case`/`job_order` access is checked against ownership
  (`ownerId` / `dentist_user_id`) server-side — frontend-supplied IDs are
  never trusted. Active once `REQUIRE_LOGIN=true`.
- Headers: Helmet CSP (`script-src 'self'`, `frame-ancestors 'none'`),
  HSTS, nosniff, no-referrer. CORS is an explicit allowlist (`CORS_ORIGINS`).
- CSRF: SameSite=Strict + `Origin`/`Sec-Fetch-Site` verification on all
  mutations.
- Input validation/sanitisation centralised (`src/utils/validation.js`),
  generic error bodies, 100 kB request cap.
